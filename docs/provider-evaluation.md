# Provider and evaluation boundaries

The no-key fixture selector and optional Gemini adapter return the same small investigation result: primary check, selected evidence, supported summary, provider/model and usage. Inputs are the three retained diagnostic findings, never imported secrets or raw original payloads. Allowed check IDs are signature, status and timeout. Exact evidence quotes must match the retained source; duplicate IDs, unknown fields, unsupported quotes and replay/destination fields are rejected. Deterministic code owns all verification and replay authorization.

## Optional Gemini configuration

Leave `GEMINI_API_KEY` empty for all offline checks. A nonempty server-side `GEMINI_API_KEY` (exported, or in `.env`, which the server loads if present) enables the optional mode; nothing else is required. Billing, quota and data-use terms belong to the key owner's Google project; the app does not inspect them. Offline CI makes no live calls. Three previously authorized synthetic live calls are recorded separately in [live validation](live-validation.md).

The fixed model is `gemini-3.5-flash-lite`, using `generateContent` with JSON-schema output, no tools and no SDK. Official [model capabilities](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite) and [structured-output contract](https://ai.google.dev/gemini-api/docs/generate-content/structured-output) informed this implementation; this exact model/schema succeeded on the three synthetic development cases in the live record. This does not establish general availability or quota. The key is sent only in the server request header. It is never returned to the browser, stored in MongoDB or included in application logs.

One durable attempt per delivery/mode prevents repeated quota use after refresh, concurrent requests or a crash. Failed/pending attempts stay visible without retry. HTTP refusal, truncated completion, malformed/oversized output and unsupported citations fail closed. No fallback or replay occurs. Requests have a 10-second bound, 1,800 output tokens and 32 KiB response limit.

## Actual evaluation and remaining acceptance

`npm test` includes a three-case fixture evaluation: expected primary checks are signature for invalid HMAC, status for HTTP 503, and timeout for the exceeded deadline. It checks exact evidence citation grounding. This is a tiny deterministic regression set, not measured live model quality. Mock HTTP contract tests check headers, limits, structured output and no execution tools; rejection tests cover injection-like fabricated citations, unknown fields, duplicate checks, refusal, truncation and oversize output. These tests do not establish provider compatibility.

The [live baseline](live-validation.md) records actual model/schema acceptance, primary-check matches, exact citations, latency and usage for the three cases. No replay was triggered. [Frozen development gates and offline scoring](evaluation.md) now cover the versioned persisted baseline. Broader/unseen-case model quality remains unverified. A second available and authorized provider configuration is required before claiming portability acceptance; the current authorization permits only the exact Gemini model above. No second provider adapter or result is claimed today. The implementation deliberately limits AI to evidence selection and supported summaries; it does not diagnose arbitrary production logs.
